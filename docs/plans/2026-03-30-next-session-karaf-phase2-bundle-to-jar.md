## Phase 2: Convert Bundle to Jar Packaging

### What

Convert 1,014 POMs from `<packaging>bundle</packaging>` to `<packaging>jar</packaging>`. Remove `maven-bundle-plugin` declarations from ~962 POMs. Remove the plugin definition from the root POM's `<pluginManagement>`.

The OSGi manifests generated by the bundle plugin are not consumed by any runtime. Spring Boot fat JARs ignore them. This is a scripted, mechanical change.

### Branch

Create: `chore/karaf-removal-phase2` off latest develop.

### Step 1: Script the POM changes

```bash
# Convert <packaging>bundle</packaging> to <packaging>jar</packaging>
# (jar is Maven default, so we can also just remove the <packaging> line entirely)
find . -name 'pom.xml' -not -path '*/target/*' \
  -exec grep -l '<packaging>bundle</packaging>' {} \; \
  | xargs sed -i '' 's|<packaging>bundle</packaging>|<packaging>jar</packaging>|g'
```

### Step 2: Remove maven-bundle-plugin from child POMs

Remove `<plugin>` blocks referencing `maven-bundle-plugin` from all child POMs. The root POM has the plugin in `<pluginManagement>` — handle that separately.

This is the trickiest scripted step because plugin blocks vary in size and content. Strategy:
- Use a script or multi-line sed to remove `<plugin>..maven-bundle-plugin..</plugin>` blocks
- Verify by grepping for `maven-bundle-plugin` after — should only remain in root POM
- Manually review any POMs that have custom `<instructions>` blocks (Export-Package, Import-Package) to confirm nothing non-OSGi is being lost

### Step 3: Remove from root POM

In `pom.xml`:
- Remove `maven-bundle-plugin` from `<pluginManagement>`
- Remove `<maven.bundle.plugin.version>` property (currently `5.1.9`)
- Check for any remaining Felix/OSGi properties and remove if unused

### Step 4: Handle edge cases

Some modules may have the bundle plugin for reasons beyond packaging:
- Modules that use `<instructions>` for `Export-Package` / `Import-Package` — these are purely OSGi, safe to delete
- Modules that use `<instructions>` for `Bundle-Activator` — also OSGi-only, safe to delete
- Any module that uses the plugin's `<_include>` or resource-generation features — unlikely but check

After removal, scan for broken POMs:
```bash
# Find POMs that still reference bundle plugin
grep -rl 'maven-bundle-plugin' --include='pom.xml' . | grep -v target

# Find POMs that still have bundle packaging
grep -rl '<packaging>bundle</packaging>' --include='pom.xml' . | grep -v target

# Both should return zero results
```

### Step 5: Remove `<packaging>jar</packaging>` lines (optional cleanup)

Since `jar` is Maven's default packaging, the explicit `<packaging>jar</packaging>` line is redundant. Optionally remove it to reduce noise. Only do this if the team prefers implicit defaults over explicit declarations.
